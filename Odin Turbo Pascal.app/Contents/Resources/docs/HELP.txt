ODIN TURBO PASCAL
Panduan penggunaan 2.8.0
Lisensi GNU GPL v3 atau yang lebih baru, hak cipta (c) 2026 Syams Ideris.

MEMBUAT PROGRAM PERTAMA

Pilih File > New. Simpan ke folder kerja sendiri dengan F2. Ketik:

program Halo;
var Nama: string;
begin
  Write('Nama Anda: ');
  ReadLn(Nama);
  WriteLn('Halo, ', Nama);
end.

Ctrl+F9 mengompilasi ulang sumber terbaru dan menjalankan executable jika
kompilasi berhasil. Program berjalan di jendela Output, di dalam jendela
utama Odin. Masukkan nama di sana, lalu tekan Enter. Alt+F5 di jendela Output
kembali ke editor; Alt+F5 dari jendela lain membuka jendela Output. Program
yang sedang berjalan tetap aktif sampai selesai atau dihentikan dengan tombol
Stop di toolbar / Ctrl+F2. Ctrl+C di jendela Output mengirim interupsi ke grup
proses.

TAMPILAN

Jendela utama Odin berisi, dari atas ke bawah:
  menu bar      File Edit Search Run Compile Debug Options Window Help, berupa
                menu teks dengan dropdown; Examples dan Open recent di menu
                File adalah submenu. Klik menu, atau tekan Alt+huruf yang
                bergaris bawah, atau F10 untuk menu File.
  toolbar       ikon New, Open, Save | Compile, Run, Stop | Debug, Trace into,
                Step over, Breakpoint | Tile, Cascade. Arahkan mouse ke ikon
                untuk melihat nama dan pintasannya.
  area kerja    jendela editor, Output, Messages, Watches, Local variables,
                dan Call stack, di atas latar abu-abu dengan logo dan versi.
  status bar    pesan, baris dan kolom kursor, INS/OVR, encoding dan line
                ending berkas.

Setiap jendela di area kerja punya bilah judul sendiri. Bilah judul jendela
aktif berwarna biru. Tombol di ujung kanan bilah judul: minimize (jendela
menjadi bilah kecil di dasar area kerja), maximize (memenuhi area kerja,
klik lagi untuk kembali), dan close. Seret bilah judul untuk memindahkan
jendela, seret tepi atau sudutnya untuk mengubah ukuran, klik dua kali
bilah judul untuk maximize. Pada awal sesi editor ada di bagian atas, Output
di kiri bawah, dan Messages di kanan bawah.

Menu Window: Tile membagi area kerja rata untuk semua jendela, Cascade
menyusunnya bertumpuk, Arrange icons merapikan jendela yang di-minimize,
Zoom (F5) memaksimalkan atau mengembalikan jendela aktif, Next (F6) dan
Previous (Shift+F6) berpindah jendela, Close (Alt+F3) menutupnya. Bagian
bawah menu Window mendaftar semua jendela; pilih salah satu untuk
mengaktifkannya.

Saat keluar, Odin mengingat jendela yang terbuka: berkas yang sudah disimpan
(beserta posisi kursor dan breakpoint), jendela Output, Messages, dan jendela
debugger, lengkap dengan posisi, ukuran, dan keadaan minimize/maximize.
Pembukaan berikutnya memulihkannya. Berkas yang sudah tidak ada dilewati.
Matikan Save desktop di Options > Environment bila tidak diinginkan.

Options > Options... membuka satu dialog bertab: Compiler, Directories, Editor,
dan Environment. Menu Options > Compiler, Directories, Editor, dan Environment
langsung membuka tab itu. Apply menerapkan perubahan tanpa menutup dialog.
Di macOS, Settings/Preferences di menu aplikasi (Command+,) membuka dialog yang
sama.

BUKU

Help > Buku membuka buku tutorial "Belajar Pemrograman Bahasa Pascal dengan
ODIN Turbo Pascal" (docs/Belajar_Pemrograman_Bahasa_Pascal.pdf) di aplikasi
PDF bawaan sistem. Buku berwarna penuh ini membahas program contoh File >
Examples (Bab 1-20), Examples - OOP (Bab 21), dan Examples - Graph (Bab 22),
bab demi bab, dengan infografik, gambar layar, rangkuman, dan latihan.

TUTORIAL PASCAL

File > Examples berisi tutorial Pascal untuk pemula: 20 bab, dari
bab01_01_halo_dunia.pas sampai proyek akhir bab20_03_buku_telepon.pas.
Nama berkas mengikuti pola babNN_MM_topik.pas, jadi urut sendiri.
Bab 1-5 fondasi, Bab 6-8 alur kendali, Bab 9-10 prosedur dan rekursi,
Bab 11-14 struktur data, Bab 15-16 pencarian dan pengurutan, Bab 17-20
file, pointer, unit, dan proyek akhir.

File > Examples - AI berisi 20 contoh pustaka AI/machine learning OTP-AI
(regresi, KNN, K-Means, jaringan saraf, Q-learning, dan lainnya), lengkap dengan
topiknya. Unit AI-nya langsung bisa dipanggil dengan uses, misalnya
uses AIMATH, AILINEAR;. Contoh dibuka sebagai templat: Save menjadi Save as.

File > Examples - Graph berisi 14 contoh unit Graph: garis dan gaya garis,
bentuk dasar, warna dan palet, isian, grafik batang, diagram pai, grafik
fungsi, animasi dua halaman, sprite dengan GetImage/PutImage, Mandelbrot, jam
analog, menggambar dengan tombol panah, dan teks. Saat dijalankan, program yang
memakai Graph membuka JENDELA GRAFIK sendiri yang menampilkan piksel
sebenarnya (640 x 480 untuk VGAHi), dan tombol yang diketik di jendela itu
diteruskan ke program (ReadKey). Jendelanya tetap terbuka dengan gambar
terakhir sesudah program selesai tanpa CloseGraph, dan hilang saat program
memanggil CloseGraph atau menjalankan program lain. Menutup jendela tidak
menghentikan program; pakai Run > Program reset. Bila Graph window dimatikan di
Options > Environment, gambar hanya tampil sebagai pratinjau kasar di jendela
Output. Contoh dibuka sebagai templat: Save menjadi Save as.

File > Examples - OOP berisi 9 contoh pemrograman berorientasi objek dengan
class: class pertama, constructor dan destructor, enkapsulasi dan property,
pewarisan, polimorfisme (virtual, override, abstract), class var dan class of,
daftar objek dengan is dan as (unit Contnrs), overload, dan proyek kasir toko.
Class adalah perluasan Odin di atas Turbo Pascal 7; ringkasannya ada di
Help > Pascal reference, bagian CLASS (PERLUASAN OOP). Contoh dibuka sebagai
templat: Save menjadi Save as.

Program Bab 17 dan Bab 20 membuat berkas data, misalnya catatan.txt atau
kontak.dat, di folder kerja program, yaitu folder berkas .pas-nya. Nama
berkas itu ditulis sebagai konstanta di awal program. Simpan dulu salinan
contoh ke folder sendiri (File > Save as) supaya berkas data mudah dicari.

EDITOR

File > Open menerima .pas, .pp, .inc dan berkas teks lain. Satu berkas dibuka
sekali dalam sesi yang sama. Tanda ● di judul jendela menunjukkan perubahan
yang belum disimpan.
Save melakukan penulisan atomik pada folder tujuan. Jika sumber diubah oleh
editor lain, Odin meminta keputusan sebelum menimpa.

Open mendeteksi UTF-8, UTF-8 dengan BOM, lalu CP437 untuk kode DOS lama.
Line ending CRLF dipertahankan. Berkas DOS yang memakai code page selain
CP437 perlu dikonversi ke UTF-8 terlebih dahulu.

File > Save as membuat salinan. Contoh bawaan diarahkan ke Save as agar source
di dalam aplikasi tidak diubah. Untuk proyek dengan beberapa unit, salin seluruh
folder examples ke folder kerja sendiri sebelum mengubah
bab19_01_pakai_unit_sendiri dan unit matematika.

Enter melanjutkan indentasi baris sebelumnya. Tab memasukkan spasi sesuai
pengaturan. Shift+Tab mengurangi indentasi baris aktif. Insert mengganti mode
insert/overwrite. Options > Editor mengatur ukuran font, lebar tab, tema, dan
warna sintaks. Command/Ctrl+= dan Command/Ctrl+- memperbesar dan memperkecil
font editor. Baris kursor diberi latar tipis. Klik kanan di editor membuka
menu Cut, Copy, Paste, breakpoint, watch, dan bantuan.

Nomor baris tampil di gutter kiri. Lingkaran merah di gutter adalah
breakpoint; panah hijau menandai baris yang akan dijalankan debugger.

Tema Terang (bawaan) memakai latar putih; tema Gelap memakai latar abu-abu
tua. Di kedua tema warna sintaks membedakan kata tercadang (tebal), variabel,
prosedur dan fungsi buatan sendiri, rutin bawaan, tipe bawaan, angka dan
konstanta (True, False, nil), string, operator, komentar (miring), dan
direktif kompiler. Matikan Syntax colors untuk teks satu warna.

SEARCH

Find mencari teks literal, bukan regex. Search again melanjutkan pencarian
dan kembali ke awal berkas bila mencapai akhir. Replace mengganti seleksi
yang cocok. Replace all mengganti semua kecocokan dalam editor aktif.
Opsi case sensitive membedakan huruf besar dan kecil pada dialog.
Go to line memindahkan kursor ke nomor baris.

KOMPILASI

Alt+F9 / F9: memanggil compiler Odin (odinpc); unit yang belum berubah
memakai hasil build sebelumnya bila masih sesuai konfigurasi compiler.
Compile > Build: semua unit dikompilasi ulang.
Ctrl+F9: kompilasi kemudian run. Tidak menjalankan executable lama saat
kompilasi terbaru gagal. Semua perubahan berkas terbuka disimpan dahulu.

Tanpa Primary file, editor aktif adalah target kompilasi. Untuk proyek yang
terdiri dari program dan unit, pilih Compile > Primary file dan tentukan
berkas program .pas. Clear primary file mengembalikan mode editor aktif.
Mengompilasi unit saja tidak menghasilkan executable, dan tidak run.

Build cache dipisahkan menurut path program dan pilihan compiler, di:
~/Library/Application Support/OdinTurboPascal/build/
Compiler tidak diarahkan untuk menimpa executable di folder sumber.
Compile > Export executable menyalin hasil build terakhir ke lokasi pilihan.
Executable hanya sesuai OS dan CPU mesin pembuatnya.

Pesan compiler tampil di jendela Messages: jenis, berkas:baris:kolom, dan
pesannya, lalu perintah odinpc dan seluruh keluarannya di bagian bawah. Saat
kompilasi gagal, kursor langsung menuju error pertama. Klik dua kali pesan
lain untuk menuju sumber, baris, dan kolomnya. Alt+F8 berpindah ke diagnostik
berikutnya, termasuk warning dan hint. Compile > Compiler messages membuka
jendela Messages.

Options > Compiler (tab Compiler):
Compiler Odin mengikuti bahasa Turbo Pascal 7, diperluas dengan class (OOP
gaya Delphi/Free Pascal). Tidak ada pilihan mode lain, dan perluasan itu tidak
perlu diaktifkan: program TP7 tetap dikompilasi seperti biasa.
Range checks dan overflow checks aktif secara bawaan.
Informasi baris untuk runtime error selalu dibuat. Debug > Start debugging
membuat build debug tersendiri dengan pengait debugger.

Options > Directories menerima satu unit/include path per baris. Path dengan
spasi didukung tanpa tanda kutip tambahan. Sumber unit pada direktori yang
sama ditemukan compiler secara otomatis.

PROGRAM PARAMETERS

Run > Parameters menerima argumen dengan aturan kutip seperti:
  "hello world" 123
Program membacanya dengan ParamCount dan ParamStr(1), ParamStr(2), dst.
Argumen diteruskan sebagai daftar, tanpa menjalankan shell.

JENDELA OUTPUT

Jendela Output memakai pseudo-terminal OS sehingga input program bersifat
interaktif. Ukuran layar emulasi 80 kolom × 25 baris. Jendela Output pada awal
sesi lebih kecil dari itu; tekan F5 untuk memaksimalkannya, atau perkecil
huruf konsol di Options > Environment (Output font size). Membesarkan jendela
tidak mengubah ukuran buffer. Klik kanan membuka Copy screen, Clear, dan
Program reset (kecuali saat program meminta mouse). Terminal mendukung bagian VT100/ANSI yang digunakan oleh CRT:
warna 16, posisi kursor, clear, scroll, insertion/deletion, dan input keyboard.
Karakter garis dan pola desktop Turbo Vision (Odin Vision) ditampilkan. Tombol F1..F12 dan Insert diteruskan ke program, termasuk
dengan Shift, Ctrl, atau Alt; F7/F8 hanya menjadi perintah debugger saat
program sedang berhenti di debugger. Program yang meminta mouse (Turbo
Vision) menerima klik, seret, dan roda mouse. Alt+huruf dikirim sebagai
Esc + huruf; di macOS, Option dipakai sebagai Alt. Setelah program Turbo
Vision selesai, isi layar sebelumnya kembali.
Ini bukan emulator terminal lengkap: tidak ada scrollback, true color, atau
akurasi lebar glyph Unicode CJK. Gunakan teks ASCII untuk program dengan tata
letak kolom yang ketat.

METRIK: UKUR DAN PERIKSA

Run > Ukur (Shift+F9) membangun program dengan build juri (odinpc build
--count-steps, dengan pemeriksaan range dan overflow) dan menjalankannya di
jendela Output seperti Run. Saat program selesai, jendela Metrik menampilkan:

  Angka resmi   langkah eksekusi, puncak heap, memori global, dan kedalaman
                panggilan. Angka ini dihitung toolchain, bukan diukur dari
                jam atau memori komputer, jadi sama di macOS, Linux, dan
                Windows untuk sumber, masukan, dan versi odinpc yang sama.
  Info mesin    waktu nyata di komputer ini; tidak dinilai.
  Peta langkah  baris yang paling banyak dijalankan.
  Catatan       saran tentang struktur kode: variabel yang tidak dipakai,
                fungsi yang tidak mengisi hasilnya, goto, nesting lebih dari
                4 tingkat, kompleksitas lebih dari 10, angka yang berulang
                atau batas larik yang sebaiknya dijadikan const, dan prosedur
                yang mengubah variabel global. Catatan tidak mengurangi nilai.

Satu langkah adalah satu pernyataan yang dijalankan; for dihitung sekali saat
masuk dan sekali per iterasi, while setiap kali kondisinya diperiksa, dan
menyalin data (assignment larik atau record, Move, FillChar) satu langkah per
64 byte. Build juri juga mengisi nol variabel lokal dan membuat Randomize
selalu mulai dari benih yang sama, sehingga hasil setiap run bisa diulang.
Klik baris berwarna di jendela Metrik untuk membuka baris itu di editor.
Simpan laporan menyimpan laporan lengkap sebagai JSON (otp-metrics/1).

Run > Periksa memilih folder paket soal lalu menjalankan program dengan
setiap kasus ujinya tanpa jendela Output. Isi paket:

  soal.md        pernyataan soal
  aturan.json    {"judul": "...", "pembanding": "trim", "toleransi": 1e-6,
                  "batas": {"langkah": 50000000, "heap": 16777216,
                            "kedalaman": 10000},
                  "syarat": ["tanpa_goto", "rekursi", "larik", "record",
                             "pointer", "prosedur"],
                  "subtask": [{"nama": "S1", "poin": 40, "kasus": ["a*"]}]}
                 semua kunci boleh tidak ada
  kasus/NAMA.in  masukan kasus NAMA, dan kasus/NAMA.out keluaran yang
                 diharapkan. Kasus berawalan "contoh" adalah contoh; yang
                 lain kasus tersembunyi.
  rujukan.pas    solusi rujukan (boleh tidak ada)

Pembanding trim mengabaikan spasi di ujung baris dan baris kosong di akhir;
exact tidak; tokens membandingkan kata demi kata; real seperti tokens tetapi
angka dianggap sama bila selisihnya dalam toleransi. Tanpa subtask, nilai =
100 x kasus lulus / jumlah kasus; subtask memberi poinnya hanya bila semua
kasusnya lulus. Hasil tiap kasus: Lulus, Keluaran salah, Runtime error,
Batas langkah (runtime error 240), Batas heap (203), Batas kedalaman (202),
Batas waktu, atau Keluaran terlalu panjang.

DEBUGGER

Program dikompilasi ulang dengan pengait debugger, lalu dijalankan di jendela
Output. LLDB, GDB, dan Xcode tidak diperlukan. Diuji di Mac Intel, dan di
runner GitHub Actions untuk Mac Apple Silicon, Linux x86_64 dan arm64, serta
Windows x86_64.

Breakpoint: Ctrl+F8 atau klik gutter kiri. Lingkaran merah ikut bergeser saat
baris disisipkan atau dihapus, dan tersimpan bersama pemulihan sesi.
Breakpoint di baris tanpa kode dipindahkan ke baris berikutnya yang berisi
kode. Breakpoint yang diubah selama sesi debug langsung berlaku.

Memulai:
  Debug > Start debugging   jalankan sampai breakpoint pertama
  F7 / F8                   mulai dan berhenti di statement pertama
  F4 / Go to cursor         jalankan sampai baris kursor
Saat program berhenti, baris berikutnya yang akan dijalankan ditandai hijau:
  F8 / Step over            satu baris; pemanggilan prosedur tidak dimasuki
  F7 / Trace into           satu baris; masuk ke prosedur yang dipanggil
  F4 / Go to cursor         lanjut sampai baris kursor
  Continue, Ctrl+F9         lanjut sampai breakpoint berikutnya atau selesai
  Ctrl+C di jendela Output  hentikan sementara program yang sedang berjalan
  Ctrl+F2                   akhiri program

Jendela Watches, Local variables, dan Call stack ada di menu Debug. Ketiganya
terbuka di kanan area editor sebagai jendela biasa, sehingga ikut diatur Tile,
Cascade, dan daftar jendela di menu Window.
Di Watches: Insert menambah, Delete menghapus, Enter mengubah ekspresi.
Nilai diperbarui setiap kali program berhenti. Double-click pada Call stack
memilih frame; Watches dan Local variables lalu memakai frame itu.

Evaluate/Modify (Ctrl+F7) menghitung ekspresi Pascal: variabel, field,
indeks (dengan cek batas), ^, @, aritmetika, perbandingan, typecast, serta
Ord, Chr, Length, High, Low, SizeOf. Fungsi program tidak dipanggil.
Modify menulis nilai baru ke variabel, dengan pemeriksaan jangkauan.
Format nilai mengikuti Turbo Pascal: 'abc', (1, 2, 3), (X:1; Y:2),
[1, 3..5], TRUE, PTR($...), dan nama enumerasi.

Jika sumber diubah di tengah sesi, perintah langkah berikutnya menanyakan
apakah program perlu dibuild ulang.

Runtime error: baris penyebabnya ditandai merah, baik saat Run biasa maupun
saat debugging. Search > Find error kembali ke baris itu.

RECOVERY

Setiap 10 detik Odin mencatat salinan isi editor ke recovery.json pada folder
pengaturan. Sumber pribadi tidak ditimpa oleh mekanisme recovery. Bila aplikasi
berhenti tidak normal, pembukaan berikutnya menawarkan pemulihan. Perubahan
pada interval terakhir sebelum snapshot mungkin belum tercatat.
File recovery dihapus ketika keluar secara normal.

TROUBLESHOOTING

Compiler not found: jalankan kembali Install.command (Install.cmd di Windows).
Dari source: cargo build --release di folder toolchain/.
Unit not found: periksa primary file, nama unit, dan Options > Directories.
ReadLn terlihat diam: klik jendela Output, ketik masukan, lalu Enter.
Tombol F1..F12 mengatur volume/kecerahan: gunakan Fn bersama tombol fungsi,
atau aktifkan penggunaan tombol fungsi standar pada pengaturan Keyboard Mac.
Font terlalu besar: Options > Editor, atau Command/Ctrl+- . Gunakan Command+B/R jika tombol fungsi
lebih nyaman dipakai untuk kontrol perangkat.
Program macet: Run > Program reset. Proses diterminasi, lalu dipaksa berhenti
jika belum keluar setelah satu detik.
Error saat membuka aplikasi: periksa launch.log dan last-error.log pada
folder pengaturan. Help > Environment information menampilkan path runtime.
