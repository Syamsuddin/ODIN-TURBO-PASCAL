• Membedakan variabel biasa dari pointer: yang satu menyimpan data, yang lain menyimpan alamat data.
  • Memakai tipe pointer ^T, operator alamat @, dereferensi P^, dan nilai nil.
  • Memesan dan mengembalikan memori selama program berjalan dengan New dan Dispose.
  • Menjelaskan struktur simpul (node) berisi Data dan Berikut, serta rantai simpul yang disebut linked list.
  • Menambah simpul di depan dan di belakang list, serta menelusuri list dengan perulangan while P <> nil.
  • Menghapus simpul di awal, tengah, atau akhir list dengan menyambung simpul sebelumnya ke simpul sesudahnya.

Sampai bab ini, setiap variabel sudah ditentukan jumlah dan ukurannya sejak program ditulis. Array dengan 100 elemen akan selalu 100 elemen, walau yang terpakai hanya tiga. Bab ini memperkenalkan pointer, alat untuk meminta memori saat program berjalan dan menyambung data satu sama lain. Dengan pointer Anda dapat membangun linked list, struktur data yang tumbuh dan menyusut mengikuti kebutuhan. Konsepnya terasa abstrak pada awalnya, karena itu bab ini banyak memakai gambar. Pelan-pelan saja, dan gambarlah sendiri setiap langkah di kertas.

Variabel Menyimpan Data, Pointer Menyimpan Alamat

Setiap variabel menempati tempat tertentu di memori, dan setiap tempat itu punya alamat, yaitu nomor yang mengidentifikasi letaknya, seperti nomor rumah di sebuah jalan. Variabel biasa menyimpan isi di rumah itu. Pointer (penunjuk) menyimpan alamat rumah lain. Analogi yang berguna: sebuah kartu nama berisi alamat sebuah toko. Kartu itu bukan tokonya, tetapi dengan kartu itu Anda tahu ke mana harus pergi, dan bila alamat di kartu diganti, Anda diarahkan ke toko lain.

Sebuah pointer selalu bertipe: pointer ke Integer, pointer ke record, dan seterusnya. Tipe ini memberi tahu kompiler bagaimana memperlakukan data di alamat itu. Pascal memakai tiga notasi yang harus dihafalkan.

Notasi pointer di Pascal
NotasiDibacaArti
^Integer"pointer ke Integer"Tipe pointer; sering diberi nama, mis. PInteger = ^Integer;
@X"alamat X"Operator yang menghasilkan alamat variabel X
P^"isi yang ditunjuk P"Dereferensi: mengakses data di alamat yang disimpan P
nil"nihil"Nilai pointer yang tidak menunjuk ke mana pun
 
type
  PInteger = ^Integer;         { tipe pointer, nama diawali P }
var
  P: PInteger;

P := @X;                     { P berisi alamat X }
P^ := 5;                     { ubah data yang ditunjuk P }
P := nil;                    { P tidak menunjuk apa pun }

Dalam Odin Turbo Pascal di macOS 64-bit, sebuah pointer berukuran 8 byte, sedangkan Integer tetap 2 byte. Jangan berasumsi ukuran pointer sama dengan ukuran Integer seperti di DOS 16-bit. Nilai alamat yang tampil di debugger juga berbeda di setiap komputer dan setiap kali program dijalankan.

Melihat alamat di debugger

Anda dapat melihat isi pointer yang sebenarnya lewat debugger. Pasang titik henti pada baris yang diinginkan dengan Debug ▸ Toggle breakpoint, jalankan dengan Debug ▸ Start debugging, lalu tambahkan X, P, dan Q lewat Debug ▸ Add watch.... Nilai pointer ditampilkan sebagai alamat bentuk PTR($...). Gambar berikut memperlihatkan bentuk tampilannya; angka alamat hanyalah contoh, alamat di komputer Anda akan berbeda.

Titik merah di gutter menandai baris yang menghentikan program, dan baris hijau adalah baris yang akan dijalankan berikutnya. Pada jendela Watches, nilai X berupa angka biasa, sedangkan P dan Q berupa PTR($...). Dua pointer yang menunjuk tempat yang sama menampilkan alamat yang sama.

Gunakan Debug ▸ Step over (F8) untuk maju satu baris dan perhatikan alamat di P berubah ketika baris 31 selesai, sementara alamat di Q tetap. Ini cara terbaik "melihat" panah pointer yang tadi digambar.

Jangan pernah mengakses P^ saat P bernilai nil atau berisi alamat sembarang. Program akan berhenti dengan galat (di Turbo Pascal: runtime error 216, general protection fault) atau, lebih buruk, merusak data lain tanpa pesan. Selalu pastikan pointer menunjuk ke tempat yang sah sebelum diikuti.

Memori Dinamis: New dan Dispose

Pointer baru benar-benar berguna bila ia menunjuk ke memori yang dipesan sendiri saat program berjalan. Memori program terbagi menjadi dua wilayah. Variabel yang Anda umumkan di bagian var berada di wilayah yang diatur otomatis. Wilayah lain disebut heap (tumpukan bebas): tempat memori bisa dipesan kapan saja dengan New dan dikembalikan kapan saja dengan Dispose. Analoginya penyewaan: New menyewa kamar dan memberi Anda kuncinya (pointer); Dispose mengembalikan kamar itu ke pengelola.

New(P);        { pesan memori seukuran tipe yang ditunjuk P; P menunjuk ke sana }
P^ := nilai;    { isi memori itu }
Dispose(P);    { kembalikan memori ke heap }

Program kedua memakai New untuk satu Integer dan untuk dua record. Untuk pointer ke record, field diakses dengan P^.Field: ikuti panah dahulu (P^), lalu ambil field-nya. Buka bab18_02_new_dispose.pas dan jalankan.

Aturan emas heap: setiap New harus punya pasangan Dispose. Catatan: record kedua yang dipesan di baris 31 menjadi tidak terjangkau (bocor), dan Dispose(B) di baris 38 membebaskan record yang sama dua kali. Simpul dan Linked List

Bagaimana bila Anda perlu menyimpan daftar bilangan tetapi tidak tahu berapa banyaknya? Array mengharuskan Anda menetapkan ukuran lebih dulu; terlalu kecil gagal, terlalu besar boros. Linked list (senarai berantai) menyelesaikannya dengan merangkai simpul (node) satu per satu. Setiap simpul berisi dua bagian: data, dan pointer ke simpul berikutnya. Simpul terakhir menunjuk nil sebagai tanda ujung rantai. Satu pointer tambahan, Awal, menunjuk simpul pertama; hilangkan pointer ini dan seluruh rantai tidak dapat dicapai lagi.

type
  PSimpul = ^TSimpul;          { boleh ditulis sebelum TSimpul }
  TSimpul = record
    Data: Integer;
    Berikut: PSimpul;          { pointer ke simpul selanjutnya }
  end;

TSimpul berisi pointer ke TSimpul lain. Definisi yang menunjuk dirinya sendiri ini tidak bermasalah, karena yang disimpan hanya alamat (8 byte), bukan seluruh simpul berikutnya.

Menambah Simpul

Ada dua tempat lazim untuk menambah simpul: di depan dan di belakang list. Menambah di depan sangat cepat, hanya tiga langkah tanpa menelusuri apa pun. Menambah di belakang harus berjalan dulu sampai simpul terakhir.

Perhatikan prosedur TambahDepan dari Program 18.3. Setiap baris di dalamnya adalah satu langkah pada gambar berikut, dan urutannya tidak boleh ditukar.

procedure TambahDepan(var Awal: PSimpul; Nilai: Integer); var Baru: PSimpul; begin New(Baru); { langkah 1: simpul baru di heap } Baru^.Data := Nilai; Baru^.Berikut := Awal; { langkah 2: tunjuk awal lama } Awal := Baru; { langkah 3: jadi awal baru } end;

Prosedur TambahBelakang berbeda dari TambahDepan: simpul baru harus dipasang ke simpul terakhir, yang hanya bisa ditemukan dengan menelusuri rantai sampai Berikut = nil. Program ini juga memiliki prosedur Tampilkan untuk menelusuri list dan HapusSemua untuk mengembalikan seluruh memori. Buka bab18_03_linked_list_tambah.pas dan jalankan.

Menghapus Simpul

Menghapus simpul dari tengah list tidak boleh sembarangan: simpul sebelum dan sesudahnya harus tetap tersambung. Triknya adalah mengingat simpul sebelumnya selagi menelusuri, lalu menyambungkannya langsung ke simpul sesudahnya sehingga simpul yang dihapus "dilompati". Setelah itu barulah simpul itu dikembalikan dengan Dispose. Simpul pertama adalah kasus khusus, karena tidak ada simpul sebelumnya; yang diubah adalah Awal itu sendiri.

Fungsi Hapus pada program berikut menerapkannya dan mengembalikan True bila nilai ditemukan. Program utama membuat list 10, 20, 30, 40, 50, lalu menghapus nilai di tengah, di awal, di akhir, nilai yang tidak ada, dan akhirnya mengosongkan list. Buka bab18_04_linked_list_hapus.pas dan jalankan.

Kesalahan yang Sering Terjadi

Mengisi pointer dengan nilai, bukan alamat

program PtrAngka; var P: ^Integer; begin P := 5; WriteLn(P^); end.

Kompiler menolak karena 5 adalah bilangan bulat biasa, sedangkan P adalah pointer. Bila maksud Anda mengisi data yang ditunjuk, tulis P^ := 5 setelah P menunjuk tempat yang sah (New(P) atau P := @Sesuatu).

Mengikuti pointer nil

Ini kesalahan paling sering saat bekerja dengan list: menelusuri sampai melewati ujung, atau memakai pointer yang belum diisi. Program berikut memakai pointer yang bernilai nil.

program NilPtr; var P: ^Integer; begin P := nil; WriteLn('Sebelum mengikuti pointer'); WriteLn(P^); WriteLn('Tidak akan sampai sini'); end.

Kompilasinya lancar, tetapi program berhenti pada baris 7 dengan galat runtime 216. Kode galat ini berarti program mengakses alamat yang tidak sah. Pada list, sumber galat yang sama adalah P^.Berikut ketika P sudah nil. Pengamannya: periksa P <> nil sebelum mengikuti panah, seperti pada perulangan while P <> nil di Program 18.3 dan (P <> nil) and (P^.Data <> Nilai) di Program 18.4.

Kesalahan yang diam: bocor dan menggantung

Dua kesalahan berikut tidak menghasilkan pesan galat sehingga sulit ditemukan.

!Memori bocor

Mengubah Awal := nil atau P := Baru tanpa Dispose membuat simpul lama tak terjangkau. Memorinya tidak bisa dikembalikan lagi. Hapus list dengan HapusSemua sebelum program selesai.

!Pointer menggantung

Memakai P^ setelah Dispose(P) membaca memori yang bukan milik Anda. Hasilnya tidak terduga. Tulis P := nil sesudah Dispose, dan jangan menyimpan salinan pointer yang sudah dibuang.

Urutan langkah yang terbalik

Pada TambahDepan, bila Awal := Baru ditulis sebelum Baru^.Berikut := Awal, simpul baru menunjuk dirinya sendiri dan seluruh list lama terputus. Pada HapusSemua, Dispose(P) sebelum Awal := Awal^.Berikut membuat Anda mengikuti pointer ke memori yang sudah dibuang. Gambarlah panah di kertas sebelum menulis kodenya; urutan yang benar biasanya tampak jelas dari gambar.

Rangkuman

  • Variabel biasa menyimpan data; pointer menyimpan alamat data. Tipe pointer ditulis ^Tipe dan ukurannya 8 byte di macOS 64-bit.
  • @X menghasilkan alamat X; P^ mengakses data yang ditunjuk P; nil berarti tidak menunjuk apa pun.
  • Q := P menyalin alamat (dua penunjuk, satu data); Q^ := P^ menyalin isi.
  • New(P) memesan memori di heap dan Dispose(P) mengembalikannya. Setiap New harus punya Dispose; sesudahnya isi P := nil.
  • Simpul linked list adalah record berisi data dan pointer Berikut. Pointer Awal menunjuk simpul pertama; simpul terakhir menunjuk nil.
  • Menambah di depan: simpul baru menunjuk Awal lama, lalu menjadi Awal. Menambah di belakang: telusuri sampai simpul terakhir dan kaitkan di sana.
  • Menghapus: ingat simpul Sebelum, sambungkan ke P^.Berikut, baru Dispose(P). Simpul pertama dihapus dengan mengubah Awal.
  • Parameter yang akan mengubah pointer awal list harus var. Debugger menampilkan pointer sebagai PTR($...).

Latihan

  1. DasarDeklarasikan X: Integer dan pointer P ke Integer. Buat P menunjuk X, ubah X lewat P^, lalu tampilkan keduanya. Gambar kotak dan panah untuk setiap langkah.
  2. DasarPesan satu Real dengan New, isi dengan hasil perhitungan (mis. luas lingkaran), tampilkan dengan format :0:2, lalu Dispose.
  3. MenengahTambahkan fungsi Hitung(Awal): Integer pada Program 18.3 yang mengembalikan banyak simpul, dan fungsi Jumlah(Awal): Integer untuk menjumlahkan data.
  4. MenengahBuat fungsi Cari(Awal, Nilai): Boolean yang menelusuri list dan mengembalikan True bila nilai ada. Pastikan aman untuk list kosong.
  5. MenengahTulis prosedur SisipUrut(var Awal; Nilai) yang menyisipkan simpul pada tempat yang benar agar list selalu terurut naik. Pertimbangkan tiga kasus: list kosong, nilai paling kecil (disisip di depan), dan nilai di tengah atau akhir.
  6. TantanganTulis prosedur Balik(var Awal) yang membalik urutan list tanpa membuat simpul baru, hanya mengubah pointer Berikut. Gunakan tiga pointer bantu.
  7. TantanganGabungkan Bab 17 dan 18: simpan isi list ke file bertipe file of Integer, lalu bacalah kembali ke list baru. Mengapa pointer Berikut tidak boleh ikut disimpan ke file?
