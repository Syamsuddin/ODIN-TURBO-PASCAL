• Menjelaskan mengapa data perlu disimpan di file, dan apa bedanya dengan variabel yang hilang saat program berhenti.
  • Mengikuti alur kerja file: Assign, buka (Rewrite, Reset, atau Append), baca atau tulis, lalu Close.
  • Menulis, membaca, dan menambah isi file teks memakai WriteLn(F, ...), ReadLn(F, ...), dan Eof.
  • Memeriksa keberhasilan membuka file dengan {$I-} dan IOResult, serta mengenali galat runtime 2 dan 103.
  • Membuat file bertipe (file of) dan memakai Seek, FilePos, FileSize untuk mengakses elemen mana pun.
  • Menyimpan dan membaca record utuh sehingga data tetap ada setelah program ditutup.

Semua variabel yang Anda pakai sampai bab ini hidup di memori, dan memori itu dikosongkan begitu program berhenti. Nilai yang diketik pengguna, hasil hitungan, daftar nama: semuanya lenyap. Bab ini mengajarkan cara menyimpan data ke file di disk, sehingga program hari ini bisa membaca data yang ditulis program kemarin. Dengan file, program Anda mulai terasa seperti aplikasi sungguhan: punya ingatan.

Mengapa Perlu File?

Bayangkan Anda mencatat nilai siswa di papan tulis. Selama papan itu belum dihapus, catatannya ada; begitu dihapus, semuanya hilang. Variabel adalah papan tulis itu: ia berguna selama program berjalan, tetapi tidak ada yang tersisa sesudahnya. File adalah buku catatan. Tulisan di buku tetap ada setelah lampu dimatikan, dan bisa dibuka kembali besok, oleh program yang sama atau program lain.

VVariabel

Disimpan di memori kerja (RAM). Cepat, tetapi hilang saat program selesai atau komputer dimatikan.

FFile

Disimpan di disk. Lebih lambat, tetapi awet: tetap ada setelah program ditutup dan bisa dibaca lagi kapan saja.

Pascal mengenal dua jenis file yang akan Anda pakai di bab ini. File teks (Text) berisi tulisan yang tersusun dalam baris-baris, persis seperti yang tampil di layar; Anda bisa membukanya dengan editor teks mana pun. File bertipe (file of sebuah tipe) berisi deretan data biner berukuran sama, misalnya bilangan atau record; isinya tidak enak dibaca manusia, tetapi cepat diakses dan rapi.

Alur Kerja File

Berbeda dengan variabel biasa, file tidak bisa langsung dipakai. Ada urutan baku yang harus diikuti, dan urutan ini sama untuk file teks maupun file bertipe. Hafalkan empat langkah berikut.

  1. Assign. Assign(F, 'catatan.txt') menghubungkan variabel file F dengan sebuah nama file di disk. Sesudah ini, semua perintah file memakai F, bukan nama file lagi. Assign belum membuka apa-apa.
  2. Buka. Pilih salah satu: Rewrite(F) untuk membuat file baru, Reset(F) untuk membuka file yang sudah ada, atau Append(F) untuk menambah di akhir file teks.
  3. Pakai. Tulis dengan Write/WriteLn, baca dengan Read/ReadLn. Perintahnya sama dengan yang sudah Anda kenal, hanya diberi F sebagai argumen pertama.
  4. Close. Close(F) menutup file. Langkah ini wajib: isi yang ditulis baru dijamin sampai ke disk setelah Close.
var
  F: Text;                    { variabel file teks }

Assign(F, 'nama.txt');       { 1. hubungkan }
Rewrite(F);                  { 2. buka (atau Reset / Append) }
WriteLn(F, data);            { 3. tulis (atau ReadLn) }
Close(F);                    { 4. tutup }

Bagaimana hubungan antara variabel F, nama file, dan isi disk? Variabel F bukan file itu sendiri; ia hanya pegangan (handle) yang dibuat Pascal untuk mengendalikan file. Mirip nomor antrean di loket: nomor itu bukan orangnya, tetapi lewat nomor itulah petugas tahu siapa yang dilayani.

Program Anda dijalankan dengan folder file .pas sebagai folder kerja. Nama file tanpa alamat, seperti 'catatan.txt', dibuat dan dicari di folder itu. Karena itu semua contoh bab ini meninggalkan file di folder tempat program sumbernya berada.

Contoh bawaan Odin dianggap template: bila Anda membukanya lewat File ▸ Examples... lalu menekan File ▸ Save, IDE akan menawarkan File ▸ Save as.... Sebaiknya simpan dulu ke folder Anda sendiri (misalnya Dokumen/Pascal) sebelum menjalankan program file, supaya berkas data yang dibuat tidak bercampur dengan berkas bawaan aplikasi. Bila perlu, ganti folder kerja lewat File ▸ Change directory....

Membaca File Teks

Menulis tanpa membaca tidak ada gunanya. Program kedua membuka catatan.txt yang baru dibuat dan menampilkan isinya baris demi baris, lengkap dengan nomor baris. Dua hal baru muncul: Reset untuk membuka file yang sudah ada, dan fungsi Eof(F) (end of file) yang bernilai True bila pembacaan sudah sampai ujung file.

Reset(F);                       { buka untuk dibaca }
while not Eof(F) do
begin
  ReadLn(F, variabelString);    { baca satu baris }
  ...olah baris itu...
end;
Close(F);

Pola while not Eof(F) do ReadLn(F, ...) adalah cara baku membaca file teks sampai habis tanpa perlu tahu berapa banyak barisnya. Eksekusinya digambarkan di bawah ini: kursor baca bergerak satu baris setiap ReadLn, dan Eof menjadi True setelah baris terakhir.

Buka bab17_02_baca_file_teks.pas dan jalankan. Karena kedua program dijalankan dari folder yang sama, program ini menemukan catatan.txt milik Program 17.1.

Dalam Turbo Pascal, membuka file yang tidak ada dengan Reset menghentikan program dengan galat runtime 2 ("File not found"). Cara menghindarinya adalah pola tiga langkah di baris 20–23: matikan pemeriksaan dengan {$I-}, buka file, hidupkan kembali dengan {$I+}, lalu periksa IOResult. Apa yang terjadi bila pengaman itu tidak ada? Program kecil berikut membuka file yang tidak pernah dibuat, tanpa {$I-}. Ia dikompilasi tanpa masalah, tetapi berhenti di tengah jalan.

Bagaimana bila Anda ingin menambah satu catatan ke catatan.txt tanpa menghapus yang lama? Gunakan Append. Perintah ini membuka file teks dan meletakkan kursor tulis di akhir, sehingga WriteLn berikutnya menyambung isi lama.

File Bertipe

File teks menyimpan semuanya sebagai tulisan. Untuk menyimpan bilangan atau data terstruktur dalam jumlah besar, cara itu boros dan lambat: angka 1000 harus diubah menjadi karakter '1', '0', '0', '0' dan dibaca balik. File bertipe menyimpan data sebagaimana adanya di memori. Setiap elemen memiliki ukuran yang sama, misalnya 4 byte untuk LongInt.

var
  F: file of Tipe;          { setiap elemen bertipe Tipe }

Write(F, X);                 { simpan satu elemen }
Read(F, X);                  { baca satu elemen }
Seek(F, N);                  { pindah ke elemen nomor N (mulai 0) }
FilePos(F)                   { nomor elemen saat ini }
FileSize(F)                  { banyak elemen dalam file }

Karena semua elemen berukuran sama, Pascal dapat menghitung letak elemen mana pun: elemen nomor N berada N × ukuran elemen byte dari awal file. Itulah sebabnya Seek bisa langsung melompat, tidak perlu membaca dari awal. Gambar berikut memperlihatkan file angka.dat yang berisi kuadrat 1 sampai 10.

Program berikut menulis sepuluh kuadrat ke angka.dat, melompat ke elemen nomor 4 untuk membacanya, mengubah elemen pertama menjadi 1000, lalu membaca seluruh file. Perhatikan bahwa file tidak ditutup di antara menulis dan membaca: file bertipe yang dibuka dengan Rewrite bisa ditulis dan dibaca, dan Seek mengatur posisinya.

Kesalahan yang Sering Terjadi

Membuka file yang tidak ada (galat 2)

Sudah dibahas pada Program 17.2: Reset atau Append pada file yang tidak ada di folder kerja menghentikan program dengan galat runtime 2. Penyebab tersering adalah salah nama, salah folder (program dijalankan dari folder lain), atau file memang belum dibuat. Periksalah dengan {$I-} dan IOResult, dan pastikan Anda tahu folder kerja dengan GetDir.

Menulis ke file yang belum dibuka (galat 103)

Lupa memanggil Rewrite atau Reset setelah Assign adalah kekeliruan klasik. Kompiler menerimanya, tetapi saat dijalankan file belum "terbuka".

program LupaBuka; var F: Text; begin Assign(F, 'x.txt'); WriteLn(F, 'halo'); Close(F); end.

Galat 103 berarti file not open. Perbaikannya: sisipkan Rewrite(F); (untuk menulis) atau Reset(F); (untuk membaca) di antara Assign dan perintah baca-tulis.

Mencampur tipe pada file bertipe

File bertipe hanya menerima nilai bertipe elemennya. Menulis string ke file of LongInt ditolak saat kompilasi.

program TipeSalah; var F: file of LongInt; begin Assign(F, 'a.dat'); Rewrite(F); Write(F, 'abc'); Close(F); end.

Lupa Close, menimpa data dengan Rewrite

Dua kesalahan ini tidak menghasilkan pesan apa pun, sehingga lebih berbahaya. Lupa Close dapat membuat sebagian isi tidak sempat tersimpan. Biasakan menulis Close(F) segera setelah menulis Rewrite atau Reset, lalu isi bagian tengahnya. Memakai Rewrite untuk menambah data menghapus semua data lama; untuk menambah, pakai Append (file teks) atau Seek(F, FileSize(F)) (file bertipe) seperti pada Program 17.5.

Rangkuman

  • Variabel hilang saat program berhenti; file menyimpan data di disk sehingga tetap ada.
  • Alur baku: Assign (hubungkan variabel file dengan nama file), buka dengan Rewrite, Reset, atau Append, baca atau tulis, lalu Close.
  • Berkas dibuat di folder kerja program, yaitu folder file .pas. Simpan contoh ke folder sendiri dengan File ▸ Save as... sebelum menjalankan program file.
  • Rewrite membuat file baru dan menghapus isi lama; Append menambah di akhir file teks dan gagal bila file belum ada.
  • Membaca file teks sampai habis: while not Eof(F) do ReadLn(F, ...).
  • File yang tidak ada ditangani dengan {$I-}, Reset, {$I+}, lalu memeriksa IOResult <> 0; tanpa itu program berhenti dengan galat 2.
  • File bertipe (file of) menyimpan elemen biner berukuran sama. Seek (nomor elemen mulai 0), FilePos, dan FileSize memungkinkan akses langsung.
  • file of record menyimpan data terstruktur; pakai string[n] agar ukuran elemen tetap, dan Seek(F, FileSize(F)) untuk menambah di akhir.
